# Сборка и подготовка выпуска MapHints

## 1. Требования разработчика

Windows, Git, Windows PowerShell 5.1, .NET SDK 8 или новее и собственная поддерживаемая копия игры. Проект мода рассчитан на net6.0, проверки правил на net8.0. Нужны BepInEx 6.0.0-be.788 и библиотеки `BepInEx/interop`, которые загрузчик создаёт после первого запуска игры. Укажите путь к игре параметром `GameRoot`. Игровые библиотеки не входят в репозиторий.

```powershell
dotnet run --project .\tests\Tests.csproj -c Release -- '<папка игры>\HeroesOldenEra_Data\StreamingAssets\Core.zip'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Installer.Tests.ps1
dotnet build .\source\MapHints.csproj -c Release '-p:GameRoot=<папка игры>'
```

Проверки установщика используют искусственные папки в `work/installer-tests`, не запускают игру и не меняют её установку.

## 2. Сборка архива

Проверьте изменения и сохраните готовое состояние в Git. Скрипт берёт исходники только из выбранного коммита. Сам `Build-Release.ps1` должен совпадать с версией в этом коммите.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-Release.ps1 -GameRoot '<папка игры>' -Revision HEAD
```

Скрипт проверяет SHA-256 игровых файлов, запускает проверки правил и установщика, собирает DLL, сверяет версию, готовит установочный архив и его SHA-256. Для расчёта состава зависимостей скачиваются закреплённые архивы BepInEx и Unity. Можно использовать уже скачанные файлы через `-LoaderArchive '<zip BepInEx>'` и `-UnityLibrariesArchive '<zip Unity>'`; их контрольные суммы проверяются так же.

Результаты в `releases/`, либо в папке `-OutputDirectory`:

- `OldenEra-MapHints-<версия>.zip`: установщик, DLL и документация.
- `.zip.sha256`: контрольная сумма архива.
- `.release.json`: версия, точный коммит, предполагаемый тег и SHA-256.

Внутри ZIP файл `release-manifest.json` перечисляет поставляемые файлы и их контрольные суммы. `_files/manifest.json` описывает устанавливаемые файлы и закреплённые зависимости. Двоичные зависимости BepInEx и Unity скачиваются самим установщиком с исходных серверов, не хранятся в Git и не входят в наш ZIP. Файлы игры, interop, сохранения и личные конфигурации исключены.

Скрипт не устанавливает мод в игру, не отправляет файлы на GitHub, не создаёт тег и не публикует Release. Существующие архивы не перезаписываются. Поле `gameplayVerified` остаётся false: автоматическая сборка не подтверждает проверку в игре.

## 3. Перед первым публичным выпуском

- Проверить именно собранный архив на чистой поддерживаемой установке: установка, первый запуск, F8, обновление с сохранением клавиш, удаление.
- Проверить в игре 0.3.12: панели университета и сыча без нижнего комментария, неизвестные здания, смена своих героев, посещение противником и загрузка более раннего сохранения.
- Проверить отметки на насыщенной карте, ежедневное и еженедельное обновление наград, отсутствие ошибок в журнале.
- Перед выпуском сверить демонстрационный снимок с итоговой версией. В README добавлен свежий снимок университета, предоставленный пользователем; ширина отображения 720 пикселей, полный размер открывается по нажатию.
- Проверить наличие MIT в файле LICENSE и в установочном ZIP, сохранить сведения о сторонних компонентах.
- Подтвердить открытие репозитория и выпуск. Сейчас проект закрыт, выпусков нет.

Проверки правил и установщика не подтверждают сетевую совместимость, все объекты кампании и внешний вид. Результаты ручной проверки фиксируйте рядом с описанием конкретного выпуска.

## 4. Публикация после проверки

Проверьте, что выбранный коммит соответствует `.release.json`. Создайте тег `v<версия>` на этом коммите и Release с установочным ZIP, `.sha256` и `.release.json`. Не перемещайте существующие теги и не заменяйте ранее выпущенный архив другим содержимым. После загрузки скачайте ZIP с GitHub и сравните SHA-256.

В описании выпуска укажите поддерживаемую сборку игры, возможности, ограничения, результат проверки в игре и ссылку на [установку](ops-admin.md). Исходники доступны в обычном дереве Git, установочные архивы размещаются в [Releases](https://github.com/yusha144/OldenEra-MapHints/releases). После первого выпуска обновите статус README. Автоматические публикации, Wiki и GitHub Actions не используются.
