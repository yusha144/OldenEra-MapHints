# Справочник MapHints

## 1. Назначение и совместимость

Отметки объектов карты, наград и доступных бонусов для выбранного героя. Мод работает внутри игры через BepInEx IL2CPP. Поддерживаемая сборка: Steam 25672315, Unity 6000.0.66.

В `source/Plugin.cs` проверяются SHA-256 двух игровых файлов: `GameAssembly.dll` и `global-metadata.dat`. Если файлы не соответствуют ожидаемым, мод не включает свою функциональность. Обновление игры требует отдельной проверки и при необходимости адаптации кода.

## 2. Состав и поток данных

Plugin проверяет файлы игры и создаёт HintOverlay. Правила посещений и наград определяют доступность отметок. Данные берутся из видимых объектов выбранного героя; метки и подсказки рисуются в игровом интерфейсе.

`source/` содержит код, `tests/` содержит проверки правил и данных, `Build-Release.ps1` готовит архив. Игровые библиотеки находятся в собственной установленной игре и подключаются при сборке через параметр `GameRoot`.

Мод не изменяет сохранения и не запускает игровые действия для получения подсказок. В памяти хранятся временные данные отображения; отдельной базы данных нет.

## 3. Настройки

Файл в папке игры: `BepInEx/config/local.oldenera.maphints.cfg`. Его создаёт BepInEx при первом запуске плагина. Обозначение `Секция.Параметр` в таблице означает параметр внутри указанной секции.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| Display.Enabled | true | Начальная видимость подсказок |
| Display.Mode | All | All, Available или Off |
| Display.IconSize | 32 | Диаметр значка, от 20 до 64 |
| Display.MarkerScale | 0.84 | Масштаб отметок, от 0.35 до 1.5 |
| Display.SkillHoverPreview | true | Показывать конкретные навыки при наведении после знакомства со зданием; пустые подсказки скрыты |
| Display.PulseManaWells | true | Выделять колодцы при неполной мане |
| Diagnostics.LogStateChanges | false | Записывать смену героя и количество отметок |

Общие клавиши читаются из `BepInEx/config/OldenEra.hotkeys.cfg`. Если его нет, используется существующий `yusha144.hotkeys.cfg`. При наличии обоих приоритет у нового файла. Если нет ни одного, мод создаёт `OldenEra.hotkeys.cfg`. В секции `Hotkeys` параметр `MapHints` по умолчанию равен `F8`. Существующие общие настройки и комментарии не перезаписываются. Настройки загружаются один раз при старте.

После ручного изменения настроек перезапустите игру. В архив не включаются личные конфигурации, поэтому при ручном обновлении DLL существующие настройки сохраняются.

## 4. Ограничения и ошибки

В версии 0.3.12 волшебный сад и мельница показывают общий кубик случайной награды. Дополнительной панели со списком ресурсов нет; при наведении остаётся штатное описание игры. Текущий выбранный вариант награды для метки не читается. Количество и вероятность выпадения не показываются. При обновлении недели метка остаётся общей.

Сыч, университет и Зловещий театр показывают дополнительную панель только после знакомства со зданием одним из героев игрока и при наличии хотя бы одного конкретного навыка. До знакомства и при отсутствии сведений о навыках мод не создаёт панель и не выводит поясняющие сообщения. Проверяется собственный список игры `DataObject.sideScoutings`, который заполняется при взаимодействии и сохраняется в партии. Покупка навыка для знакомства с университетом не требуется. Знание доступно всем своим героям, но посещение другим игроком его не раскрывает. После загрузки используется состояние выбранного сохранения, включая старые сохранения; отдельного файла истории мода нет. У Странствующего цирка дополнительной панели нет.

Разделитель / между значками ресурсов или характеристик означает выбор одной награды. Он применяется в том числе к деревне и пряничному домику. У случайной награды используется кубик, поскольку вариант выбирает игра.

Панели известных навыков не содержат общего комментария об условиях обучения и не резервируют для него пустое место. Если часть предложений не удалось определить, остаётся отдельное сообщение о неполном списке.

Изменения требуют проверки в игре перед публичным выпуском. Специальные объекты кампаний могут не поддерживаться.

Автоматические проверки охватывают выделенные правила и обработку данных. Они не подтверждают внешний вид, все игровые механики или сетевую совместимость. Проверка в игре остаётся отдельной частью подготовки выпуска.

## 5. Диагностика

В проверенном окружении сообщения BepInEx записываются в `BepInEx/LogOutput.log`. Ищите название мода и сообщения об отсутствии поддерживаемой сборки или ошибке запуска. Для подробностей о смене героя и отметках временно включите Diagnostics.LogStateChanges, затем верните false.

В обращении укажите версию мода, Steam build, воспроизводимые действия и соответствующий фрагмент журнала. Перед публикацией журнала проверьте, нет ли в нём личных данных.
